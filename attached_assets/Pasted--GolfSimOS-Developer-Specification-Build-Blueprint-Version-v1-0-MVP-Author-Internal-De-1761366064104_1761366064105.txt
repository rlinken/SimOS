🏌️‍♂️ GolfSimOS — Developer Specification & Build Blueprint
Version: v1.0 (MVP)
Author: Internal Dev Team @ GetMoreViews / Adam Linkenauger
Purpose: Build the operating system for indoor golf simulator businesses — unifying bay bookings, memberships, lessons, fittings, and payments, with native integrations for Stripe and GoHighLevel.
🧠 1. System Overview

GolfSimOS is a full-stack SaaS web application for simulator-based golf facilities.
It replaces multiple tools (Bookee, GoHighLevel calendars, separate CRM systems) with a single command center.

Core Modules

Smart Bay Booking System

Real-time availability calendar

Bay rotation & wear-tracking logic

Tiered access (by membership type)

Membership Management

Subscriptions via Stripe

Hourly credits, renewals, access control

Lessons & Lesson Packages

Instructor scheduling, package tracking

Instructor → client linking

Club Fittings

Fitter calendar, intake forms, follow-ups

Integrations

Stripe → payments, subscriptions, invoices

GoHighLevel (GHL) → CRM, email, SMS, automations

Admin Dashboard

Revenue overview, booking utilization, member reports

⚙️ 2. Architecture Overview

Frontend:

React + Vite + TailwindCSS

🔌 5. API Design
Authentication

Handled by Supabase Auth (JWT)

Authorization: Bearer <token>

POST /api/bookings

Creates a booking

{
  "user_id": "uuid",
  "start_time": "2025-02-01T10:00:00Z",
  "end_time": "2025-02-01T11:00:00Z",
  "type": "rental"
}


Response:

{ "booking_id": "uuid", "status": "confirmed" }


Logic:

Validate user tier → allowed bays

Assign lowest-use bay matching tier

Update bay usage_hours

GET /api/bays/available?start=...&end=...

Returns available bays by time window.

POST /api/memberships

Creates or updates membership.
Triggers Stripe subscription creation → returns stripe_checkout_url.

POST /api/lessons

Creates lesson booking; optionally links Stripe payment.

POST /api/fittings

Creates club fitting booking.

POST /api/integrations/ghl/contact

Sync user with GHL:

Create contact if none

Tag user by membership tier

Send optional note (“Booked Bay 3 - 10am”)

🧠 6. Business Logic: Bay Rotation

Pseudocode:

function assignBay(userTier) {
  const eligibleBays = bays.filter(b => 
    b.status === 'active' && 
    membershipTiers[userTier].includes(b.tier)
  );
  return eligibleBays.sort((a,b)=>a.usage_hours - b.usage_hours)[0];
}


Every completed booking increments usage_hours.
If usage_hours > 100 → mark as rotation_due → staff alert.

💳 7. Stripe Integration

Memberships → Stripe Subscriptions

Rentals/Lessons/Fittings → Payment Links or Checkout Sessions

Webhooks:

invoice.payment_succeeded → Update booking/payment status

customer.subscription.updated → Update membership data

customer.subscription.deleted → Cancel membership

💬 8. GoHighLevel Integration

Outbound (GolfSimOS → GHL):

On user signup → POST /contacts

On booking → POST /notes

On lesson/fitting complete → add tag (e.g., “Lesson Complete”)

On membership renewal → add tag “Active Member”

Inbound (GHL → GolfSimOS):

Webhook → create user or booking (lead conversion)

Webhook endpoint: /api/webhooks/ghl

🧩 10. Error Handling

All API errors follow JSON format:

{ "error": "message", "code": 400 }


Logged to Supabase errors table.

Webhook retries handled via idempotent keys.
